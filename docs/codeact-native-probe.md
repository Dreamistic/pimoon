# CodeAct 原生执行入口验证与迁移候选

## 决策

迁移候选为一个 JSON 原生 `execute` 工具，承载 Python 源码；内部函数不变成模型工具。保留现有 Python Runtime、批处理、路径权限、逐项审批和取消机制。本次仅验证协议，不修改生产默认，不做后台提前执行。

原生 custom 文本工具也已跑通，但当前小样本未显示优势，暂不引入第二套生产适配。

## 2026-11-05 实测

命令：`node scripts/probe-codeact-native.mjs --live`

SDK 支持 grammar constrainedSampling 转为 custom 工具；本实验在模型副本中显式设置 grammar 支持，通过 onPayload 验证真实声明类型。JSON 模式使用 strict require。SDK 可能把声明放在 input.additional_tools，检查不能只查看顶层 tools。

首次尝试因只检查顶层 tools，在 onPayload 本地拒绝全部六次请求，未执行 Python；修正声明位置后完整运行通过。

结果 `.tmp/tests/codeact-native/run-jLFzyB/`，源凭据未改变；访问凭据仅只读使用、不刷新、不落盘。配置、输入、输出均隔离。没有真实桌面审批或会话恢复验证。

## 下一阶段实施边界

1. 先在隔离完整 AgentSession 中接入单个 execute，参数为 code、desc 和可选 confirm。模型可见的内部函数目录保留，但不注册成模型可调用工具。
2. 仅正常原生 toolUse 终态后执行；本轮多个 execute、错误参数或异常终态拒绝执行，先验证整个调用集合再启动任何一个，不能执行第一个后才发现第二个。
3. 整块意图确认与内部逐项权限检查必须保留。不可把新入口当作绕过现有审批的捷径。
4. 覆盖多轮变量保持、写入恰好一次、拒绝确认、运行中取消、模型失败、重开会话及历史回放，禁止自动重放已有副作用。
5. 用真实业务场景进行相同模型、相同内部函数目录和相近提示词的交错对照，记录端到端耗时、正常结算覆盖率、额外 token、错误和重复执行。
6. 通过后再替换生产纯文本协议；不长期保留双协议兼容层。旧文本会话应先明确迁移方式（如只读历史、新建执行会话），不能直接混放工具结果或伪造调用身份。

验收不是仅“能调用”：完整业务结果正确、无权限回归、无重复副作用、失败状态清楚，并且结算可靠性较截流改善。没有足够证据就不切默认。

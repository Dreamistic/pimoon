# Sol 单场景三轮对测

2026-11-05。沿用 [Terra 对测](terra-accounting-comparison.md) 的发票读取与汇总场景，只测试这一场景，不修改生产代码、默认模型或桌面包。

## 条件与计量

- `gpt-6.1-sol / low / SSE / runtime prompt`，o-pi 和 pimoon 各 3 个独立会话，轮次间交错执行顺序。
- 使用同一 Codex 订阅、同一 SDK、相同文件夹具和独立验收器。只加载当前系统提示词、文件工具及 pimoon CodeAct，不是完整桌面产品对测。
- 本场景读取 12 张发票、忽略 void、检查预期不存在的 missing.json、写入汇总，并校验原始发票未改动。
- 所有用户目录与临时目录隔离。访问凭据只读、经 stdin 传入内存存储，不刷新、不落盘；最终源凭据指纹未变化。
- 轮数含最终回答。工具时间使用根执行区间并集，不重复相加并发与嵌套调用。
- Token 沿用可见载荷 `o200k_base` 估算，工具分项包含说明/目录、历史调用、历史结果和新调用；不是供应商精确用量，也不是订阅节省率。
- 当前源码仍含既有未提交执行器草稿。与此前 Terra manifest 相比，打包输入仅公共 token-accounting 模块有完整性检查方面的变化，提示词、工具和执行器未变；两次模型实验发生在不同时段，不是同时随机配对的模型速度证明。

## 与此前 Terra 同场景比较

| 指标 | o-pi / Terra | pimoon / Terra | o-pi / Sol | pimoon / Sol |
| --- | ---: | ---: | ---: | ---: |
| 总时间中位数 s | 19.198 | 35.818 | 25.405 | 24.829 |
| 模型轮数中位数 | 4 | 4 | 4 | 5 |
| 动作响应耗时中位数 s | 4.034 | 9.408 | 8.105 | 5.448 |
| 多文本消息的动作响应 | 0/9 | 8/9 | 0/9 | 0/11 |

- pimoon 换 Sol 后，本组总时间中位数比此前 Terra 低约 30.7%；o-pi 换 Sol 则更慢。因此不能推导出 Sol 在所有执行协议和任务下都更快。
- Sol 的 11 个 CodeAct 动作响应全部直接输出执行块，没有此前 Terra 的反复进度前言。这支持“模型对文本执行协议的适配存在差异”，但不等同于已经隔离服务端推理与网络波动。
- pimoon 第 1、3 次会话将带展示包装的 read 返回文本直接交给 json.loads，发生 JSONDecodeError，各多用一轮自行纠正后通过。原始失败与耗时保留，没有重跑替换。
- 每会话检查 missing.json 引发的内部读取失败是预期业务分支，与上述两次 JSON 解析误用分开看。executionErrors 是事件计数，不是任务失败率。
- 这次更直接的优化候选是避免 read 展示文本与原始 JSON 的混用，再复测是否能减少修复轮次；没有据本实验改动函数接口或切换原生执行协议。

## 后续防误用改动

- 保留 `read` 的展示返回值，在真实 output schema 中说明它不是原文；函数目录现在保留顶层及联合分支的返回说明，提示 JSON/CSV 解析使用已有 `native_read(path)`。
- 提示词将可用目录的限制明确为宿主工具，不再含糊限制 Python 内置辅助函数和标准库。没有新增工具、模式或自动转换。
- 对展示文本引发的 `JSONDecodeError` 附加诊断，保留原始异常；真正损坏的原始 JSON 继续报原来的错误。不自动剥标签、重读、重试或重放写入。
- 离线 SDK/Python 流程覆盖错误复现、原文读取后一次执行块完成 12 张发票汇总、预期缺失文件，以及原文标签、Unicode、CRLF 保真。定向 5 个测试文件共 60 项及全项目类型检查通过。

这不是新的真实 Sol 速度或误用率实验；以上三轮数据不变，不能声称已经少一轮或进一步提速。原文读取与编辑前版本观测的区别见 [CodeAct 使用说明](reference/codeact/README.md)。

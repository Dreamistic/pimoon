# Terra 模型流等待诊断

2026-11-04；沿用 pimoon 的有效 Codex 访问凭据与隔离合成工作区，不改真实模型、思考档位或传输配置，不请求加价 service tier。

## 可以加速哪些部分

- 客户端能影响传输重连、提示词/上下文、模型轮次和协议误用；不能直接控制服务器排队与模型推理速度。
- 单纯压缩 Python 或文件工具不是当前重点：根执行通常只有几百毫秒。
- **本轮没有证实可直接上线、稳定显著加速 gpt-6.1-terra 的改动。** 未将关闭思考、提示词试验或其他模型强加给现有会话。

## 先校准基准条件

此前 [工具对测](terra-tool-comparison.md) 的隔离 SDK 会话没有指定 transport，也没有加载项目的 system-prompt 扩展，实际采用 SDK 默认 auto 与 SDK 提示词。pimoon 桌面初始配置使用 SSE，并加载项目提示词；因此不能把旧 SDK 耗时直接当作桌面实际耗时，也不能把切换 SSE 宣称为新增的桌面优化。

基准现在显式选择并记录：

- `--transport=sse|auto`，默认 sse。
- `--prompt=runtime|sdk`，默认 runtime，加载各自仓库真实的 system-prompt 扩展。
- `--thinking=low`，以及模型支持的其他思考档位。
- `--apps=pimoon` 可单独测试，避免每次额外消耗 o-pi 对测请求。

runtime 模式仍然只是定向 SDK/工具链测试，不是完整桌面宿主；没有加载真实项目上下文、全部扩展或历史会话。

## 分段实测

新增探针记录逻辑请求开始到首个供应商事件、首个正文 delta、执行标记识别、执行开始和结束的相对毫秒数；只保存数字和非敏感请求元数据，不保存原始供应商事件。实际 payload 同时验证 reasoning.effort、工具声明数量和 CodeAct 指令是否存在，避免只相信 UI/测试参数。

一次 `gpt-6.1-terra / low / SSE / SDK prompt` 定位编辑任务：

| 首轮事件 | 请求开始后的时间 |
| --- | ---: |
| 首个供应商事件 | 1.740 秒 |
| 首个 thinking summary | 4.764 秒 |
| 首个正文与 CodeAct 开始 | 15.782 / 15.783 秒 |
| 开始执行 | 15.794 秒 |

此请求只有一个正文消息，仍然等待了约 15.8 秒才出现代码，说明重复前言不是唯一瓶颈；也不能把这段全部解释成 TCP 建连。分段数据不能进一步精确区分服务器排队、推理和网络抖动。

## 尝试结果

均为实际模型完成后校验文件的合成任务，小样本，不是性能保证。

| 条件 | 定位编辑结果 |
| --- | --- |
| 6.1 Terra / low / SSE / runtime | 两次通过，34.26、45.93 秒，4、5 次请求 |
| 5.6 Terra / low / SSE / runtime | 两次通过，19.69、34.30 秒，均 4 次请求 |
| 6.1 Terra / off / SSE / SDK prompt | 一次失败，30.38 秒；模型未输出执行块 |

批量发票汇总：6.1 Terra / low / SSE / runtime 一次通过，50.45 秒、4 请求；5.6 Terra 相同条件一次通过，29.80 秒、5 请求，但多出一次执行失败事件。不能据此认为旧模型在真实任务中必定更快或更可靠。

另一提示词试验明确说明宿主会执行文本、鼓励在一个块中串联已知步骤：汇总一次通过、30.97 秒；定位任务在收到首个事件后一直没有正文，180 秒超时。无法将超时归因于提示词，也没有可靠提速证据，因此已撤回该提示词改动，不计入以上原提示词的模型对照。

直接 off 的失败不证明所有 off 任务都失败，但已经不足以安全推荐“关闭思考即可加速”。不自动修改用户默认档位。

## 当前建议

1. 保持桌面已有的 SSE；不要为了复用连接直接切 auto，需验证截流后的连接与上下文缓存行为。
2. 简单任务可手动试 5.6 Terra / low；本次样本较快，但时延范围重叠，只能作为候选。
3. 减少实际模型轮次与重复查询，保留编辑前读取、失败检查和修改后验证；不为缩短耗时越过安全边界。
4. 若要求继续保留 6.1 Terra 并明显提速，下一项应是**受控比较纯文本协议与单个原生执行入口**。这涉及当前“API 不声明工具”的架构要求，应单独确认与验证，不能伪装成无风险的传输参数优化。
5. 没有测试加价优先通道；未经确认不启用，也不承诺订阅支持或固定收益。

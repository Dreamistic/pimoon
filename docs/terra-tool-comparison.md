# Terra 真实工具调用对测

2026-11-04，Windows、Node 24.18.0，使用 **pimoon 的 Codex 订阅 / gpt-6.1-terra / low**。没有启动 Electron。

后续[模型流分段诊断](terra-stream-latency.md)确认本页历史样本采用 SDK 默认 auto 传输和 SDK 提示词，不是桌面的 SSE / 项目提示词。新基准已显式区分这些条件；下表不能当作桌面耗时或切换 SSE 的收益。

## 结论

- 同一模型完成相同合成文件任务：o-pi 原生工具与修正后的 pimoon 文本 CodeAct 均通过三个场景。
- **当前 pimoon 更慢，不能宣称 CodeAct 已获得端到端优势。** 减少模型轮次不等于减少等待时间。
- 当前瓶颈在模型流等待，不在 Python 桥接或文件工具。最后完整一轮中，pimoon 的模型流累计约 34.8–46.3 秒，CodeAct 执行累计仅 0.18–0.29 秒。模型流时间包含网络、生成与客户端流处理，不是纯服务器推理时间。
- 提前截流的响应普遍没有完整 usage；较低的已报告 token **不是**真实总量或订阅节省证据。

## 方法与边界

分别打包 `D:/Code/githubproject/o-pi` 和本仓库的文件扩展，共用借用的同一 Pi SDK、解析 worker 与模型；pimoon 另外绑定当前源码 CodeAct 和 Python 执行资源。模型可用能力均为 read/write/edit/find/grep/ls，只有 pimoon 使用 Python 编排。

这是真实远程模型 + SDK + 工具执行链路对测，不是两个安装版的完整宿主、系统提示词、GUI 或端到端产品对测。没有启用其他扩展、技能、进程或网页工具。pimoon 工作树已有执行器/遥测草稿被实际测到，但没有纳入本次提交。不得把工作树实测等同于纯提交快照实测。

三个场景：

1. 25 个 TS 文件中定位运费实现，精确修改门槛并复读；校验目标文件与所有其他夹具。
2. 12 张 JSON 发票过滤作废项、按客户汇总并写文件；额外检查不存在文件，校验全部原始发票和输出。
3. 8 个配置中条件精确修改 4 个、复读全部文件、写排序后的修改列表；逐字节校验格式与未修改项。

每个场景独立新会话和工作区。场景与轮次交错改变两应用顺序；上限为每会话 12 次逻辑模型请求、180 秒，进程另有 240 秒上限。请求数为 SDK 流调用次数，不是单独测得的 HTTP 传输重试次数。耗时包含会话初始化、模型/工具循环、校验与清理，不含打包、准备资源和创建 ModelRuntime 的时间。

只读 pimoon 的有效访问凭据；不读取原版配置，不携带真实刷新令牌。访问凭据经 stdin 传入进程内只读存储，不落盘、不打印、不刷新。子进程的 PIMOON_HOME、HOME、USERPROFILE、APPDATA、LOCALAPPDATA、TEMP/TMP 和 SDK agentDir 全部隔离。模型只处理合成工作区。

## 已实施的改动

### 独立文本块的执行标记

真实 Codex 响应会先产生不带末尾换行的说明消息，再在另一个正文块中输出 `<execute>`。旧解析器将它们作为同一行拼接，合法执行块可能被当成普通文字，模型继续空转。

现在独立正文块有自己的行首，原文和代码不插入换行；源码跨块续传、结束偏移、原文签名、围栏/thinking 示例保护、供应商失败和取消检查不变。合成回归先复现两项失败，修正后通过；真实 SDK 内存 SSE 覆盖前置说明块、主动截流、完整和超限终态及只执行一次后继续下一轮。

### 函数目录与编排说明

- 实测 terra 曾把 `batch(name,jobs)` 的 name 写成发票目录名或任务名称。提示词明确它是 read/find/grep/ls 函数名；不增加工具入口或模型回合。
- schema 原有的 `minLength` 在紧凑函数目录中丢失，模型用空 find 查询枚举路径而失败。现在目录保留字符串最小长度，由 schema 生成，不重复维护工具规则。
- 要求动作直接输出执行块并等待真实结果，不发送进度前言。该指导没有消除全部模型延迟，不能宣称稳定提速。

在仅有文本块修正的一轮，pimoon 汇总需 5 请求，条件编辑需 6 请求，出现错误 batch 名和空查询。补充目录/提示后的一轮分别为 4 和 5 请求；最终完整一轮为 4 和 4 请求，未再出现这两类误用。样本很少，提示词改动未做多次随机对照，不能把全部波动归因于修改。

汇总任务中的 missing.json 失败是预期业务分支，不算缺陷。结果文件的 executionErrors 统计失败事件；嵌套失败和根执行失败可能同时计数，不能直接当作独立错误或重试数。

## 复现

已有桌面资源构建及有效 pimoon 访问凭据时：

```powershell
node scripts/bench-live-tools.mjs --live --upstream=D:/Code/githubproject/o-pi --model=gpt-6.1-terra --thinking=low --transport=auto --prompt=sdk --runs=1
```

可用 `--scenarios=locate-edit` 限制订阅消耗；没有 `--live` 不会请求模型。不安装依赖、不修改上游或真实配置。新运行会保存打包源码输入的指纹、合成对话/执行结果和完整指标，均留在忽略目录；不将私人会话或凭据提交到 Git。

后续应优先评估 terra 对文本执行协议的遵循与模型流延迟，必要时另开受控 A/B 比较入口协议。不要为了几十毫秒的宿主开销放松审批、读前校验、取消或路径保护，也不要直接恢复已删除的混合工具架构。

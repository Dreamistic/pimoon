# 自主记忆与跨工作区操作设计

状态：设计基线，初版及审批反馈整合已实现。当前能力与限制以[自主记忆说明](../reference/memory/README.md)和[审批链路](../reference/approval-gate/README.md)为准；本文件还包含后续目标。适用范围：当前验证的 Windows 桌面分支。

## 1. 目标与固定边界

让 AI 自己积累、查阅和修订可复用的经验，而不是让用户维护知识库。记忆覆盖用户纠正、排错经验、环境陷阱、项目决策和资料入口；审批只是来源之一。

固定以下边界，后续扩展不改变它们：

1. 记忆正文是普通 Markdown，AI 使用现有文件工具维护，不增加重复的记忆 CRUD 工具。
2. 只自动提供受预算限制的简短索引。是否读取、读取哪篇正文，由 AI 决定；不默认检索并注入正文。
3. 记忆文件是唯一内容事实源；索引和搜索缓存均可从文件重建。
4. 工作区是任务上下文，不是普通文件操作的硬边界；风险检查依据操作与目标，而不只是目录归属。
5. 记忆不是权限、系统指令或最新事实保证。AI 能自由修改经验，不因此获得自行扩权的能力。
6. 不依赖会话结束时成功运行一次总结。主模型在正常工作过程中记忆，不常驻第二个总结模型。

不在第一版实现：向量数据库、知识图谱、自动全历史提炼、云同步、独立记忆代理、跨机器身份推断、将记忆自动编译为授权。

## 2. 当前接入条件

| 现有位置 | 已有能力或限制 | 设计影响 |
| --- | --- | --- |
| `src/harness/system-prompt/service.ts` | 集中构造角色与命名提示词段落 | 放置短记忆规则，不将所有记忆正文塞入 system prompt |
| `src/harness/extensions/prune.ts` | 在 `context` 事件修改请求投影 | 记忆索引可在请求构造阶段接入，不改写历史模型消息 |
| `src/harness/file-tools/runtime/host.ts` | 文件观测、会话版本、写入回执 | 复用并验证这些能力，不另造一套记忆编辑器 |
| `src/pimoon/codeact/session.ts`、`src/pimoon/paths.ts` | 普通 `write/edit` 被额外限制在工作区内 | 需要改为操作风险判定；不能只开放一个 memory 目录例外 |
| `src/pimoon/worker.py` | 原生 Python 写入也限制在工作区；另有网络、进程、FFI 限制 | 原生 I/O 必须同时审计，不能只修改工具路径检查 |
| `src/harness/approval/` | 确定性审批规则与独立授权存储 | 与记忆分离，复用真实审批结果作为经验来源 |

底层文件工具已经支持显式访问工作区外路径，但 CodeAct 入口仍有限制。当前 Python audit hook 和路径检查不是操作系统沙箱，不能宣称能隔离任意已批准的外部程序。

本设计不修改已有执行协议，也不承诺 CLI/Web 同时交付。

## 3. 存储、范围与身份

所有数据仅位于 `PIMOON_HOME`，不读取原版 `.pi`，不自动导入 `.claude`。

```text
PIMOON_HOME/memory/
  projects.json
  user/
    MEMORY.md
    entries/
      feedback-response-style.md
  projects/<project-id>/
    MEMORY.md
    entries/
      lesson-partial-execution.md
      project-build-decision.md
```

- `entries/*.md`：AI 和用户维护的内容事实源；第一版仅发现直属 Markdown 文件，不递归跟随链接。
- `MEMORY.md`：程序生成的完整活动记忆索引，不包含正文；允许显式读取和搜索，不要求整体进入上下文。
- `projects.json`：宿主维护的版本化项目身份映射，不是模型需要编辑的文件。
- 范围由文件位置决定，不在 frontmatter 再保存一份可能冲突的 scope。

### 项目身份

以规范化后的 Git common directory 识别同一仓库，使同仓库 worktree 共享记忆；非 Git 项目使用会话绑定的工作区根目录。处理 Windows 大小写、真实路径和 junction 别名。Python 的 `chdir` 不改变会话绑定。

宿主首次登记时分配稳定 ID。仓库搬迁、同一远端的不同 clone 不自行合并；用户可显式将新位置关联到已有记忆。远端 URL 不作为唯一身份，也不写入模型索引。

### 项目与用户范围

默认写入当前项目。只有用户明确表达跨项目偏好，或经验确实不依赖当前项目、版本和环境时，才写入 user 范围。未确定范围时保留在项目内。

当前会话默认只获得 user 和当前项目的索引。跨项目文件访问不自动加载其他项目的记忆；任务明确涉及另一项目时，可显式发现其记忆目录。该选择是相关性控制，不是文件访问禁令。

分支切换不复制记忆。与特定分支、版本、系统相关的经验必须在正文注明条件，不能因属于同一项目就假定仍适用。

## 4. 记忆格式

保留 Claude Code 风格的短 frontmatter 和自然语言正文，增加独立的 `lesson` 类型承载可复用的坑。

```markdown
---
name: 失败后先核实副作用
description: 执行包含写入的代码块报错或取消后，判断是否可以重试时读取
type: lesson
---

适用：CodeAct 代码块包含文件修改或外部副作用。

结论：失败不代表回滚；重试前检查已完成的步骤。

Why：错误可能发生在部分写入完成之后，整块重跑会重复副作用。

How to apply：核对目标状态，只补做未完成的步骤。
```

字段约束：

| 字段 | 语义 |
| --- | --- |
| `name` | 简短标题，单行，最多 80 个 Unicode 字符 |
| `description` | 何时值得读取，单行，最多 160 个 Unicode 字符；不是全文摘要 |
| `type` | `user`、`feedback`、`lesson`、`project`、`reference` |
| `status` | 可选，默认 `active`；`archived` 不进入自动索引 |

文件名是范围内的稳定标识；优先使用短、可搜索的主题名，避免每次修改都重命名。一篇解决一个可复用的问题，不将一次会话全部塞入一篇。

正文按需表达条件、结论、原因、做法和依据，不强制所有文章拥有相同小标题。易变事实写明系统、工具版本或其他有效条件。未验证推断不能写成已验证结论；必要的假设明确标注，不能凭模型自述提升为可信事实。

时间与写入来源由宿主根据文件元数据、文件工具回执和会话条目记录，不要求模型生成 UUID、时间戳或真实性标签。外部编辑只能标记为外部变更；来源记录用于排错，不充当授权凭证。

Frontmatter 使用非执行式 YAML 解析，只读取已定义字段；未知字段不参与索引或授权判定。格式错误或超限文件仍保留在磁盘，但不进入有效索引；写入反馈和记忆界面指出具体问题。旧的有效摘要不能在源文件已经无效时继续冒充最新内容。第一版单篇有效记忆上限 32 KiB；大段日志、代码和附件只记录引用。

## 5. 索引与按需读取

### 完整索引

宿主从有效、活动的 frontmatter 生成：

```markdown
- [失败后先核实副作用](entries/lesson-partial-execution.md): 执行包含写入的代码块报错或取消后，判断是否可以重试时读取
```

只使用标题、描述和相对文件路径，不自动提炼正文。转义 Markdown 特殊字符，保留原始 Unicode；程序标签、状态和模型侧分隔符使用紧凑 ASCII。

AI 修改正文及摘要即可，不负责同步索引。对派生 `MEMORY.md` 的编辑不成为事实源；工具反馈提示修改对应 entry，外部改动会被重建结果替代。

### 请求中的索引预算

第一版自动提供的记忆上下文总上限为 8 KiB UTF-8、80 条摘要，任一达到即停止加入整条记录。目录说明、标题和溢出提示也占预算。这是字节预算，不宣称等价于固定 token 数。

两个范围先各分配一半预算，未用完的额度交给另一范围。按类型、稳定文件名排序，不随每次读取改变顺序；不让最近编辑的文章不断挤走其他索引。具体预算集中为实现常量，先测量再决定是否需要用户配置项。

索引头始终给出两个范围的绝对目录、条目相对路径基准和最小格式提示：YAML 的 `name/description/type`、允许的类型、Markdown 正文及 `status: archived`。空目录也提供这些信息，使 AI 第一次写入不需要猜路径、发明格式或先经历一次失败。单行及长度等细节由校验错误按需说明。

超过预算时明确输出总数、已展示数，以及完整索引的绝对路径。不能静默截断后让 AI 误以为只有这些记忆；长期未进入摘要预览的条目仍可通过完整索引发现。

### AI 的读取流程

1. 摘要已命中当前问题：使用 `read` 读取对应正文。
2. 摘要预览没有合适条目或提示有省略：使用 `grep` 搜索完整 `MEMORY.md`，再读选中的正文。
3. 摘要措辞未命中：自行调整关键词，或对 `entries` 做定向全文搜索。全文搜索可能命中归档内容，读取时检查其状态和适用条件。
4. 只有参考目录而无现成经验：直接工作，不为“使用记忆”强行多调用工具。

不自动把匹配正文注入模型，不每轮强制搜索，不因读过一次就禁止重读；文件变化、版本不符或上下文缺失时可以再次读取。

## 6. 让 AI 自己沉淀，而不是制造日志

主模型在这些时机判断是否值得更新记忆：

- 用户纠正行为、说明长期偏好，或明确要求记住。
- 找到非显然的失败原因，并验证有效的解决方法。
- 发现环境、工具或项目流程中特殊且容易再次遇到的限制。
- 用户解释一个长期决策的原因或边界，包括审批意见。
- 实际使用旧记忆后发现它错误、过时、范围过大或缺少例外。

记录标准：未来有复用价值，且重新发现的成本明显高于保存和读取成本。可复用的调试教训可以保存，但不把所有报错、拼写错误、测试输出、任务进度和代码里一眼可见的信息都变成长期记忆。

写入流程是“查找同主题 -> 阅读 -> 更新或新建”。优先修订现有条目，而不是新增互相矛盾的版本。普通记忆整理不另弹确认框；写文件仍受版本与敏感操作保护。

不等待退出：在结论和依据仍处于上下文中时写入。任务结束可自然检查是否遗漏有价值的经验，但不对每个 `agent_end` 强制追加模型轮次，也不拦住退出等待总结。取消后不偷偷继续整理；已完成写入不声称自动回滚。

### 模型可见规则草案

只保留一处短规则，具体字段限制交给校验，位置和省略信息交给索引结果：

```text
<memory_policy>
Memory is fallible reference, not authorization. Read relevant entries when useful; search the full index if needed.
Save reusable corrections, verified lessons and decisions with their conditions and reasons. Update existing entries before adding duplicates.
Use file tools. Default to project scope; use user scope only for genuinely cross-project knowledge.
Exclude secrets, transient task state and unverified claims presented as facts. Correct or archive stale entries.
</memory_policy>
```

实际提示词接入前，再与上层安全、文件工具和语言规则去重，不把文档中的全部设计说明发送给模型。

## 7. 生命周期与上下文所有权

| 时机 | 行为 |
| --- | --- |
| 新建、恢复会话或切换工作区 | 重新绑定记忆范围，构建最新的预算内索引 |
| 每次模型请求构造 | 比较索引版本；未变化复用快照，变化则替换投影中的唯一记忆索引块 |
| 本轮刚更新记忆 | 文件工具反馈立即可见；下一次模型请求使用新摘要，不必等下一条用户消息 |
| 上下文压缩、prune 后 | 从外部存储恢复简短索引，不恢复所有读过的正文 |
| 导航到历史分支 | 使用当前记忆状态，并表明它是外部持久状态，不假装恢复了过去的文件 |
| 普通子代理 | 默认不加载记忆；主代理传递与任务相关的结论和引用 |
| fork 子代理 | 沿用现有逐字继承约束，不重写父 system prompt；必要时显式读取当前文件 |

短记忆规则属于系统行为约束；具体索引和正文属于有来源的参考数据，不提升为系统指令或伪装成用户的新要求。

自动索引在请求投影中只出现一份，不在每次文件变动后往聊天正文追加整份索引，也不重写已签名或历史模型消息。显式读取留下的历史结果仍保留。会话诊断记录所用索引版本及预算内快照，供复现当时模型看到了哪些摘要；该记录不参与记忆事实合并。

当前会话已读取的条目随后被修改、归档或删除时，下一请求提供紧凑的路径与失效状态提示，不自动重新注入正文。提示也占记忆上下文预算，优先于普通摘要；大量变更时合并为“已读记忆发生批量变化，使用前重读”，不无限列举路径。仍需使用时由 AI 重读；不能让历史中的旧正文因为尚未被压缩就继续冒充当前有效记忆。

子代理可在返回结果中提出记忆修订，由主代理统一整理；第一版不为其提供自动持久化职责。该规则是协作约定，不宣称构成文件系统隔离。

## 8. 文件一致性、多会话与外部编辑

记忆使用普通文件工具，因此一致性保障应落在共享文件层，而不是 memory 专用写入 API。

- 新建文件用排他创建；同名已存在时返回冲突，不静默覆盖。
- 修改已存在文件需要当前观测版本；另一个会话修改后，返回过期读取，要求重读和重新合并。
- 提交前版本比较和原子替换处于同一个协作锁范围；不能只在各会话里分别串行。若多个宿主能共享同一个 `PIMOON_HOME`，须覆盖跨进程协调。
- 写入成功的正文立即成为事实源。索引失败不回滚正文，也不诱导 AI 重复执行写入；反馈区分 `saved` 与 `index_pending`。
- 索引以源文件集合的版本快照生成，原子替换；若生成期间源文件改变则重试。索引损坏或丢失可以重建，不需要双文件事务。
- 文件工具写入回执负责即时标脏；文件监听负责外部编辑提示。监听事件不是可靠账本，启动和请求前核对直属条目的目录元数据负责兜底，不每轮重读全部正文。
- 只重新解析变化文件。外部编辑尚未写完整时暂不收录，文件稳定后再校验；坏文件不影响其他条目。

外部编辑器或已批准的原生程序可能不遵守协作锁，无法承诺与其并发写入绝对无冲突。受控文件工具间保证版本检查；外部变更尽力检测，发现不一致必须显式报告。AI 默认用文件工具维护记忆，不能通过换成 Python 覆盖来回避过期版本错误。

用户可直接编辑 Markdown。UI 提供查看、编辑、归档、删除和关闭自动记忆；自动写入用不抢焦点的简短提示展示，不弹审批。归档是 `status: archived`，方便 AI 停用错误经验而不必执行删除。

删除或归档后立即失效索引缓存。关闭自动记忆停止自动索引加载与自动沉淀，不删除文件。已有会话里的正文不会因此凭空消失；真正清除聊天记录属于另外的显式操作，不承诺“遗忘”自动抹除所有历史副本。

## 9. 跨工作区自由与安全边界

### 目标行为

普通目录的读取、新建和已读文件修改，不因位于工作区之外而被拒绝。相对路径仍基于当前工作区，跨目录操作使用明确路径，不悄悄改变会话归属。

| 行为 | 处理 |
| --- | --- |
| 普通文件读写，包括工作区外目标 | 默认允许，保留版本、路径真实性和 OS 权限检查 |
| 未读文件覆盖、并发过期修改 | 先读或重读；无理由扩大授权不能解决数据冲突 |
| 删除、批量破坏性修改、系统关键位置和提权 | 按风险进入现有审批，不以普通目录通行代替授权 |
| 凭据访问、敏感外发 | 独立敏感策略；不随普通文件权限一起放开 |
| 授权记录、安全策略和防护配置变更 | 受独立策略保护，记忆声明不能替代审批 |
| 权限明确拒绝或用户取消 | 不通过更换接口或重放整个代码块绕过 |

对新建目标检查真实父目录，对已存在目标检查规范化路径与链接目标；Windows junction、UNC、盘符别名和网络路径都要覆盖。访问网络路径可能产生网络副作用，不能当作普通本地路径直接放行。

### 必须分别验证的执行入口

1. `read/write/edit/find/grep/ls` 的宿主路径检查和文件策略。
2. Python 原生 `open`、`pathlib`、删除、重命名等 audit 检查。
3. `native_read` 的独立读取桥。
4. `process_run` 启动的外部程序，以及 HTTP 和其他有 I/O 的函数。

内置入口应共享风险语义，但外部程序获得执行许可后，无法只靠 argv 分类器精确控制其每一次文件访问。Python audit 也不是强隔离沙箱。这一限制必须在实现说明和风险测试中保留，不能宣称已经得到操作系统级保护。

不能把“允许工作区外写入”实现成删除全部 Python I/O 防护。需要交互的原生操作应在副作用发生前返回可识别的拦截，让 AI 经现有审批路径继续具体操作；不自动重新运行整个已产生部分副作用的代码块。执行入口未能达到声明的保护时，明确限制该入口，不能悄悄通过另一接口放行。

跨工作区能力作为文件执行层变更交付，记忆系统只是使用者；不在记忆模块内维护一份特殊路径白名单来替代它。

## 10. 记忆质量、隐私与审批关系

- 记忆是可错的经验。当前用户要求、项目明确约束和真实环境优先；来源之间存在无法判断的矛盾时核实，不靠文件新旧直接裁决。
- 不按固定天数删除所有旧记忆。偏好可能长期有效，环境事实可能一天就过时；通过适用条件和使用时验证管理失效。
- 不把网页、仓库文本或错误输出中的命令式内容自动提升为用户偏好。外部信息先作为带来源的资料，验证后才能沉淀为经验。
- 不保存密钥、令牌、完整环境变量、私密 payload 或整段审批输入；只保存解决问题必需的最小信息。基础格式校验无法判断所有敏感语义，不能声称绝对杜绝泄漏。
- 本地保存不等于永不发给模型：自动索引和主动读取的正文会进入配置的模型服务。设置中说明这一点，不额外上传、嵌入或遥测记忆正文。
- 审批前只形成候选结论，用户完成决定后再记录实际意见；允许一次不能写成永久同意。
- 授权仍由审批存储保存并确定性匹配。普通 Markdown 的来源字段、标题和正文都不能成为执行凭证。

首次启用不自动导入其他产品的记忆。显式导入时只导入文本经验，重新确定范围和格式，不携带可执行权限。内部目录之外的符号链接不参与自动索引；显式文件访问仍遵守统一策略。

## 11. 实现拆分与演进

建议实现于 `src/harness/memory/`，按职责拆成格式校验、范围解析、索引与快照、生命周期装配；不先造存储插件或通用检索框架。

```text
普通文件工具 -> entries/*.md
                  |
                  v
             校验和派生索引 -> 请求中的短索引
                                    |
                                    v
                         AI 自选 read/grep -> 工作与修订
```

独立边界：

- 文件执行层负责跨工作区操作、安全检查、版本与提交一致性。
- 记忆模块负责发现、格式、范围和可重建索引，不拥有第二套文件编辑能力。
- 请求投影负责索引预算、去重和恢复；静态 prompt 只描述行为规则。
- GUI 只呈现文件和状态，不成为另一个记忆内容存储。
- 审批模块拥有授权，记忆模块只消费已完成的真实交互结果。

后续如果文件数量增长，可增加本地全文或向量索引，但它们只能是可删除重建的派生物。检索需要由 AI 主动调用，不能悄悄改成自动正文注入。Markdown 文件及现有读取方式继续有效，无需迁移内容事实源。

### 交付顺序

1. 文件层：定向审计各 I/O 入口，落实跨工作区普通操作与共享版本保护，标明无法提供的强隔离保证。
2. 最小闭环：项目/user 范围、格式校验、派生索引、受预算的上下文、普通工具写入和即时刷新。
3. 可靠性与可见性：多会话、外部修改、取消恢复、归档删除、关闭开关及不抢焦点的记忆管理界面。
4. 审批整合：将真实审批结果作为额外经验来源；不让记忆模块承担授权迁移。

第二步是可定向验证的开发切片，不应跳过第三步就宣称完整交付。第一版不依赖第四步才有价值：修 Bug、用户反馈和一般任务均能自主积累经验。

## 12. 验收与验证

| 真实流程 | 必须观察到的结果 |
| --- | --- |
| 排错后记录有效教训，新会话再遇到相关任务 | 只自动看到短摘要，AI 可以主动读取并应用正文 |
| 没有相关记忆的普通任务 | 不强制读取全部记忆，不强制额外总结轮次 |
| 索引超预算，目标条目未进入预览 | 明确告知省略，完整索引可搜到该条目 |
| 更新、归档、删除或破坏一篇文件 | 下一请求不保留该条目的过期有效摘要，其他条目不受影响 |
| 两个会话先读后改同一文件 | 后提交者收到冲突，不静默覆盖前者 |
| 正文保存后索引更新失败或宿主退出 | 正文保留，重启可重建索引，不重复执行原任务 |
| 切换工作区、worktree、恢复或导航会话 | 范围正确，不把外部持久文件假装回滚到历史状态 |
| 相同内容经普通工具、Python 原生和进程路径访问 | 覆盖各入口声明的策略；未覆盖的隔离能力明确记录 |
| 尝试将外部网页指令写成授权记忆 | 即使文本存在，也不能改变运行时授权结果 |
| 关闭自动记忆 | 不再自动加载索引或主动沉淀，不偷偷删除文件 |

优先单元与集成测试：格式与预算、项目身份、索引重建、跨会话版本、请求投影去重、入口风险回归。AI 是否愿意主动记忆还需代表性多轮评测；不把“提示词已加入”当作行为保证，不把调用工具次数越多当作质量越高。

记录自动加载字节数、正文主动读取次数、保存/冲突/无效条目数等必要诊断，不记录记忆正文。GUI 如需验证只运行定向无头测试；不常规启动桌面或跑全量 E2E。

所有测试将 `PIMOON_HOME`、`HOME`、`USERPROFILE`、`APPDATA`、`LOCALAPPDATA` 指向隔离测试目录；不在真实配置中创建记忆，不修改借用的 `node_modules`。

# 显式并发执行界面

## 用户可见行为

- 执行卡片收起时显示“已并发 · 峰值 N · M 组”；没有显式组的新版已完成执行显示“未使用并发组”。只提交单项或实际没有重叠的组不冒称已经加速。
- 展开卡片可查看“并发执行”面板：每组任务数、失败策略、状态、组耗时、实际峰值，以及每个操作的函数、目标、开始偏移和耗时条。包含 native_read，不依赖 SDK 是否有子工具卡片。
- 运行中的组默认展开，显示等待派发/执行中/完成/失败/未启动/已中断；手动折叠不被实时更新覆盖。执行完成沿用现有父卡片自动收起行为。
- 重叠时长按各操作耗时之和减去执行区间并集计算，包含工具/审批等待；不是相对串行的实测节省，也不是整轮加速。中断没有完整数据时显示未完整记录，不补零。
- 旧记录只有 batch_peak_concurrency 时显示“仅汇总”，不从源码、函数数量或参数猜测历史时间线。

## 实现边界

- Runtime 在真实调度开始/结束边界采样，独立回调通过 execute 的 SDK 进度更新进入正式 GUI；最终 details.scheduling 留在会话记录，重开和大输出引用仍可读取。
- 不改变并发算法、工具权限、失败策略或副作用顺序。调度路径/目标不进入数值遥测，元数据也不进入模型正文。
- 单次执行最多保存32组、256项详情，目标最多160字符；达到上限明确标记截断。分组统计仍按实际事件记录，不把未展示项当未执行。
- 进度最多每80ms刷新一次，组开始/结束立即刷新；末尾更新与取消清理计时器。回调不可用不改变业务执行。
- 使用主题语义色、薄填充、可折叠组和窄容器换行；不新增弹窗或抢焦点操作。

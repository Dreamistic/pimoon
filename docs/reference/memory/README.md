# 自主记忆

当前交付范围为 Windows 桌面。AI 在正常工作过程中自主保存用户纠正、验证过的排错教训、项目决策和资料入口，不依赖退出时再调用一个总结模型。

## 加载与读取

- 每次请求仅自动提供短索引，不自动加载正文。总预算为 8 KiB UTF-8、80 条摘要，目录说明和失效提示也占预算。
- 详细记忆由 AI 自选 `read`；预览中没有相关内容时，可用 `grep` 搜索完整 `MEMORY.md`，再读正文。
- 索引超预算明确显示已展示数与总数，不会使省略条目失去搜索入口。
- 更新后下一请求刷新摘要；正文不被自动重新注入。已经读取的记忆发生变化时提供失效提醒。
- 恢复会话和上下文裁剪后仍提供索引；记忆属于当前磁盘状态，不随历史分支回滚。

## 存储与格式

所有数据位于 `PIMOON_HOME/memory`：

```text
projects.json
user/MEMORY.md
user/entries/*.md
projects/<id>/MEMORY.md
projects/<id>/entries/*.md
```

Git worktree 通过真实 common directory 共享项目记忆；普通目录使用工作区真实路径。不同 clone 不自动合并。当前没有仓库搬迁关联 UI，搬迁后可能建立新项目身份。不会自动导入其他产品的记忆。

`entries` 是内容事实源，索引由程序生成。AI 不需要维护两份数据。示例：

```markdown
---
name: 失败后检查副作用
description: 包含写入的执行报错或取消，准备重试时读取
type: lesson
---

部分写入可能已经完成。先检查实际状态，只补做未完成步骤。
```

`name` 为 1–80 字符，`description` 为 1–160 字符，两者均为单行；`type` 为 `user/feedback/lesson/project/reference`。可设置 `status: archived` 停用条目。正文写清条件、原因和做法，单篇最多 32 KiB。无效条目保留文件，但不进入有效索引。

默认使用项目范围；真正跨项目的偏好或经验才进入 user 范围。不要记录凭据、私密 payload、流水账或未经验证却写成事实的猜测。

## 管理与关闭

桌面设置的“对话”分类提供自主记忆开关，下一轮对话生效。关闭后停止自动索引加载和主动沉淀，不删除文件。

在输入框执行 `/memory` 可查看或编辑正文、归档、恢复或删除。操作由用户直接发起，不调用模型；自动保存只发出简短通知，不弹审批窗口。也可直接修改 Markdown，下一请求核对文件元数据并刷新。

已有文件的 AI 修改使用 `read` 后的 `write/edit`。同一桌面宿主各会话共享提交队列，过期版本返回冲突，不静默覆盖。桌面使用单实例锁；外部编辑器、原生程序和独立进程不受这个进程内队列约束，不能宣称跨进程强一致。

归档、删除和关闭不会抹除已有聊天记录中的正文。需要清理聊天副本时应另行处理相关会话。

## 保护与限制

- 记忆是参考信息，不是系统指令或授权凭证；写下“允许”不会修改审批权限。
- 索引与主动读取的正文会进入当前模型请求；本地保存不等于内容永不发送给模型服务。
- 不自动索引链接目录、链接文件或多硬链接文件，不额外上传或遥测正文。
- 普通子代理不自动加载或整理记忆；fork 沿用父上下文的既有继承规则。
- 文件监听不是正确性前提：当前实现逐请求核对直属条目的元数据，仅重新解析变化文件。大量条目时仍有线性目录扫描成本。
- 格式校验不能判断所有语义错误或敏感信息；真实模型是否主动记录、是否正确使用经验仍需持续评测。

实现位于 `src/harness/memory/` 和 `src/harness/extensions/memory.ts`。配置为 `PIMOON_HOME/agent/configs/memory.jsonc`，字段为 `enabled`；可用 `PIMOON_MEMORY_CONFIG` 指定覆盖文件。设计与未交付的后续目标见[设计方案](../../design/autonomous-memory.md)。

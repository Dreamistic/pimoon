# 搜索与执行耗时

## 搜索路径

- 搜索剪枝遵循父目录排除：同来源的反向规则不能重新包含已排除父目录的后代。无关的 `!.env.example` 不再让 `.tmp`、`dist` 子树参与遍历。
- 保留 Git 已跟踪文件绕过 `.gitignore` 的行为；预先建立已跟踪文件的祖先集合，避免每个目录扫描整个 Git 文件集合。
- 更高优先级来源仍可重新包含后代。剪枝前只检查当前目录自身的高优先级规则，不递归忽略子树寻找深层例外。需要深层例外时应先在可达规则中重新包含父目录。
- 显式指定被忽略目录仍可搜索，显式读取仍可用；权限与保护路径检查不变。
- 纯文本和非空纯文本分支（如 `foo|bar`）直接使用 ECMAScript RegExp，省去 worker 启动与逐批通信。包含量词、分组、转义、断言等其他正则继续使用可终止 worker，保留后向引用与取消语义。

正文与语法缓存、文件版本复验、扫描并发和 LSP 预热仍沿用现有实现。未新增跨调用目录快照缓存，避免文件新增、策略变化或并发取消导致漏搜；未引入 Rust 正则替换。

## 计时口径

`grep` 成功结果的 `timing` 只进入 details 和遥测，不增加模型正文：

| 字段 | 区间 |
| --- | --- |
| `inventory_ms` | 路径、可见性、目录发现与快照 |
| `scan_ms` | 正文读取/缓存复验与文本匹配 |
| `analysis_ms` | 扫描后剩余的 LSP 预热等待与语义分析 |
| `regionize_ms` | 语法区域生成 |
| `rank_pack_ms` | 排序、打包与输出计量 |
| `total_ms` | 上述顺序阶段之和，不含工具外围审批/配置初始化 |

遥测将 `total_ms` 投影为 `search_total_ms`。预热与扫描的重叠区间不重复相加。失败或取消未完成流水线时不伪造完整阶段计时。

每个已完成调用还记录：

- `wall_ms`：从工具开始事件到结束事件的单调时钟跨度。
- `approval_wait_ms`：收到审批状态事件后观测的等待；`approval_wait_complete=false` 表示结束时尚缺审批终态，该样本不进入完整审批耗时分布。
- `process_duration_ms`：仅来自 `process_run` 自身的结果，包含进程启动、执行与退出清理。
- 原 `duration_ms` 仍保留 SDK 口径。审批工具可能在 execute 内等待，不能把它和审批等待直接相加。

后台遥测同时记录 `approval_start/end`。同一模型请求只记录一次 `model_end`，工具取消后追加的合成 assistant 错误记录为 `assistant_end`，不重复计算模型请求耗时。

会话工具报告的“耗时拆分”展示这些观测值，包括 CodeAct 内部搜索。旧记录缺失不补零；父子调用及并行调用不相加作为整轮耗时。

## 并发扫描预算

同一 `GrepTool` 实例的查询现在共用最多 8 路（不超过逻辑核数一半，至少 1 路）文件扫描预算，而不是每个查询各开最多 8 路。排队项可独立取消；一个查询取消不清空其他查询的队列。这个上限只约束扫描阶段，不是全应用所有磁盘 I/O 的总上限。

没有复用权限裁决或目录快照，不跳过路径保护、正文缓存的版本复验，也不改变匹配、排序、覆盖统计或截断语义。尚未引入跨调用在途正文读取合并。

```text
bun scripts/bench-codeact-search.mjs 3 --concurrent
```

并发基准运行四个固定查询，单列每批墙钟 `batchMs`，不能将四个调用耗时相加。2026-11-05 的三次局部采样中，批次中位数约 6.078 s → 5.489 s；两组均搜索 1,518 个文件，命中数和截断原因一致。这是先前后后的同机小样本，缓存和系统负载会影响结果，不足以宣称稳定提速。资源上限、排队取消与结果正确性另由真实文件搜索测试验证。

## 模型往返

CodeAct 指导要求复用持久变量，在结果或用户选择改变计划前，在同一块完成已知步骤；独立调用使用 batch，依赖步骤先检查结果，输出仅保留下一次决策所需内容。没有自动并行共享写入、没有自动放行审批，也不承诺提示词改变一定减少模型轮数。

## 复现基准

```text
bun scripts/bench-codeact-search.mjs 3
```

脚本将 PIMOON_HOME、HOME、USERPROFILE、APPDATA、LOCALAPPDATA、TEMP、TMP 全部指向独立 `.tmp/tests/search-benchmark/run-*`，只读当前仓库，使用独立工具配置，不启动 GUI、LSP 或模型。原始结果保存在同目录。首轮包含惰性初始化，后续复用正文和语法缓存。

2026-11-04 本机源码路径采样（每查询 3 次，含首轮）：

| 查询 | 改动前中位数 | 改动后中位数 |
| --- | ---: | ---: |
| `PIMOON_HOME` | 2.772 s | 1.440 s |
| `enabledModels\|selectedModels\|scopedModels` | 2.849 s | 1.474 s |

遍历条目从命中 10,000 上限降为约 1,800；实际搜索文件从约 1,150 增至约 1,490，不再因 `entry_limit` 漏扫。展示仍可触发 `result_limit`，不等同扫描不完整。采样期间工作区有新增源码，且文件系统缓存与负载会影响数值；这不是冻结仓库的严格 A/B，也不是桌面端历史 13 秒调用的重放。

新的阶段数据中正文读取/匹配仍占主要搜索耗时，不能仅凭该墙钟判断为 CPU 热点。后续应区分文件系统等待与匹配 CPU，再决定是否需要原生扫描核心。

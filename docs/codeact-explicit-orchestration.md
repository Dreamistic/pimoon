## 范围与契约

- 保留持久同步 Python、print、条件、断言、循环、标准数据处理；普通调用严格串行。
- 删除隐式 AST 自动并行；新增显式 parallel(jobs, errors="raise")，jobs 为 (已启用只读函数, 参数字典) 列表，可用推导式动态生成。
- 第一版只允许 read/find/grep/ls/native_read；写入、进程和未知函数不得进入并发组。最多 256 项、宿主最多并发 6；不暴露线程/任务句柄。
- 默认失败停止继续派发，已派发读取可能完成；失败携带逐项状态，不自动重试。errors="collect" 收集全部逐项成功/失败，不隐藏部分失败。
- 组结果按输入顺序返回；普通 Python 在组间表达数据依赖、阶段屏障和副作用顺序。
- 保留 print，增加多组旧/新写法教学，说明并发范围、顺序链、动态映射、失败收集和输出。
- 不实现竞速、自动重试、事务补偿、通用 DAG DSL、自动写入并发或结果仓库。

## 实现与迁移

- `parallel([(read, {"path": "a.txt"}), (grep, {"query": "TODO"})])` 返回按输入次序排列的值。集合用推导式产生任务列表；参数不是已经执行的函数结果。
- 删除 `auto_parallel.py` 与运行时 `autoParallel` 开关，不再根据赋值、打印或推导式自动派发。旧普通 Python 程序仍可串行执行，旧隐式并发实验脚本移除。
- `parallel`、`ParallelError`、`ToolError` 为 Python 保留名称。每块重新绑定工具；旧代理不获得新并发资格。宿主仍独立检查允许的只读函数与权限。
- 组描述全部完成基本校验才派发；每项权限、实际参数 schema 和路径仍由宿主在调用边界检查。不要把这一点误称为所有任务能预先通过权限审核。
- 宿主 isError 无论是否带 structuredContent 都抛 `ToolError(RuntimeError)`，`.code` 保留文件工具错误码；未知错误为 TOOL_ERROR。此处是行为变更：不再把结构化执行失败作为正常值继续依赖步骤。
- 并发收集提供 `error_code`：native_read 缺失为 ENOENT，read 缺失为 FILE_NOT_FOUND；未知代码不当成缺失。原生读取在并发组外的既有异常协议暂未改动。
- print 保持 Python 的同步输出语义，未增加自动摘要或偷偷裁剪；已有展示上限、预览及变量保留不变。

## 真实模型试用与改进

Codex 订阅，Sol `gpt-6.1-sol` 与 Astra `gpt-6-astra`，low/SSE；不在任务提示里指定 parallel 源码，教学来自真实 execute 声明。测试配置、输入、输出均在 `.tmp/tests`，源 OAuth 只读、stdin 传递、禁止刷新，所有 manifest 验证源凭据未变。

1. 首版：两个模型各三场景两轮，共 12 次，产物与流程全部通过，34 次响应 usage 完整。全部自然使用 parallel，合计 23 组、峰值 6；没有把 edit/write/进程放进并发组。可选缺失输入全部自然采用 errors="collect"。
2. 暴露的不足：模型仍可能打印中间源码/配置再进入下一轮；read 是展示文本，JSON 处理和编辑观测仍可能各读一遍。独立配置检查为 3–4 个模型请求，不能声称所有确定性流程已经一块完成。
3. 两模型起初靠多种自然语言片段识别缺失错误。因此增加 native_read 的系统 error_code。两个补样都生成正确输入错误码判断，却在检查输出文件是否存在时错误套用到 read：各出现一次根执行错误，下一轮恢复且不重放输入或写入。两次失败恢复样本保留，没有从数据剔除。
4. 最终补齐宿主文件工具错误码与单项 ToolError.code，并明确两个缺失代码。两模型各补一次可选输入任务，均一个 execute 加最终回复完成，根执行错误为零；预期的内层缺失仍保留为部分失败，不伪装全部成功。

总计 16 次任务均最终通过，分属三个实现阶段，不可把 16 次都冒称最终版本样本。逐次数据见 `docs/benchmarks/codeact-explicit-orchestration.json`。没有完整会话旧/新对照，不能据此承诺省 token 或整轮提速。

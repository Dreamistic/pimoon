# Terra 计量补齐与三轮对测

2026-11-05，Windows，Node 24.18.0。结论：**本组任务 pimoon 少模型轮次、可见载荷更小，但总耗时更高。供应商真实总 Token 仍不能比较，不能将本地估算当作额度节省。**

后续只切换模型的发票汇总结果见 [Sol 单场景三轮对测](sol-aggregate-comparison.md)。

## 本次计量变化

- `model_request/model_end` 分别记录请求可见载荷和响应可见输出的本地 Token 估算，不记录正文。所有估算使用同一个 `o200k_base`。
- 供应商用量分为 complete、partial、unavailable。仅当每次请求都有完整用量时，`provider_total_tokens` 才有数值；否则为 null。已报告数单独保留，绝不和本地估算混加。
- 工具输入拆为说明/函数目录、历史调用、历史结果；工具输出单列本轮生成的调用。历史在后续请求重复输入时重复计数；内部 I/O 没有回填模型的内容不计模型输入。
- 同时识别顶层 tools、Responses 的 additional_tools/tool_search_output，以及 CodeAct 协议/Functions 目录。不能只看顶层 tools 数量判断原生工具是否存在。
- 审批顾问使用独立请求 ID，保留主请求关联；成功、失败和取消都记录辅助请求终态，和主模型分账。
- `tool_end.returned_text_tokens` 只表示该函数返回文本，不是模型实际输入 Token。CodeAct 内部调用可能不回填、被投影或被替换。
- `scripts/pimoon-report.py` 输出 `summary.token_accounting.main/auxiliary`。旧日志没有正文和估算时保留未知，不倒推不存在的计量。

本地估算是**可见请求 JSON 与输出的 BPE 体积**，不是供应商精确计数：包含序列化结构与部分标识，不含隐藏思考、图片、加密内容及未接收的服务端生成。不同协议的估算偏差可能不同。本轮 o-pi 可见总估算 110,198，而其完整供应商总量是 71,394，直接说明不能把两种口径互换，也不能凭同一个本地分词器就证明订阅用量同比例减少。

## 方法

- 两边同用 pimoon 现有 Codex 访问凭据，`gpt-6.1-terra / low / SSE`；没有刷新凭据、切换服务等级或回退模型。
- o-pi 源码基线为 `D:/Code/githubproject/o-pi`；分别加载两边当前 system-prompt 和文件工具，pimoon 使用当前文本 CodeAct。
- 3 个合成文件任务，各重复 3 次，共 18 个独立会话，按轮次和场景交错顺序。不是把每个子工具计成一轮。
- 每会话最多 12 次逻辑模型请求、180 秒；父进程另有 240 秒上限。不启动 Electron，不加载私人项目上下文、历史会话或全部桌面扩展。
- 轮数是逻辑模型请求数，包含最终作答。总时间包含会话初始化、模型/工具回路、验收和清理，不含打包与 ModelRuntime 创建。
- 工具时间是根执行开始/结束区间的并集：原生并发工具不重复相加，CodeAct 不再加一遍内部函数耗时。另保留根执行累计值供诊断，但不拿它当墙钟。
- 总/工具 Token 的可比列均采用上述本地估算。工具 Token = 说明/目录输入 + 历史调用输入 + 历史结果输入 + 新调用输出，是总估算的归因部分，不能再加到总量上。
- HOME、USERPROFILE、APPDATA、LOCALAPPDATA、PIMOON_HOME、TEMP/TMP 和 SDK agentDir 全部隔离；访问凭据仅经 stdin 传给内存存储，不落盘。源凭据最终指纹保持不变。

这是**当前源码的定向模型/工具链实验**，不是完整桌面产品排名。执行器和工具报告的既有未提交草稿被实际测到，但没有混入本次提交；每个应用的实际打包输入指纹保存在本地 manifest 中。

## 解释与限制

- 18/18 通过，但不代表每步无误。发票场景的缺失文件是预期分支；pimoon 条件编辑首轮另有一次将函数对象传入桥接、无法 JSON 序列化的执行失败，模型自行纠正后通过，未删除或重跑刷分。
- 工具墙钟两边都不到总时间的 2%。约 158 秒的累计总时间差，模型流差约 157 秒，仍不是 Python 执行器导致的主要差距。
- pimoon 条件编辑有一次 86.710 秒，明显存在远程生成/传输波动。每场景仅 3 次，不报告有意义的 P95 或统计显著排名。
- 本组审批顾问未启用，没有额外辅助模型费用。生产路径已补独立顾问终态计量，并用隔离测试覆盖。
- 请求与响应本地计量累计约 o-pi 129.6 ms、pimoon 42.7 ms；实际墙钟未扣除此开销。工具返回文本的计数和其他遥测开销仍计入实际链路，不宣称零成本。
- 截流仍然保留，没有为了获取 usage 等待完整供应商终态，也没有额外发模型请求“补账”。因此尚未得到当前默认截流路径下的完整真实 Token 对比。
